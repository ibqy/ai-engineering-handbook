# 图片传给模型为何看不懂

## 直接回答

先区分没有收到图片、无法解码和收到但识别错误。把网址写进提示词不等于提交图片媒体；即使媒体传递成功，小字、旋转、压缩和任务歧义也会影响答案。应逐层验证传输、解码与识别，不要仅靠追加“仔细看”修补链路。

## 实际场景

用户上传设备铭牌，系统能描述设备，却读错型号。应检查原图与模型实际接收的版本，确认缩放是否损失笔画，再保留全图并增加铭牌裁剪图。问题要明确要求型号、对应区域及无法辨认的字符，不允许用常见型号补齐缺字。

## 原理与取舍

图片输入需要正确的媒体封装和已核验支持该输入的模型配置。文件扩展名、响应头都不能单独证明真实格式，应检查文件签名并在资源限制下解码。分辨率提升或多裁剪可能保留细节，也增加传输、处理成本，并可能丢失全局关联。

生产入口宜使用经过授权的受控上传。若必须接收远程地址，应限制协议、域名、端口与解析后的地址，阻断内网、回环和本地资源；重定向每一跳都重新校验，连接时防止地址校验与实际访问不一致。下载需限制字节数、时长和解码像素数，不能信任声明长度；鉴权信息不得跨域转发。

## 实现示例

以下为设计伪代码，未运行；步骤名称不代表任何现成接口，也不演示任意网址下载。

```text
输入：已授权用户、受控上传对象、识别问题
校验用户对对象的读取权限
限制文件字节数；检查实际类型；受限解码
若格式不支持或资源超限：返回明确错误
保留原图标识与裁剪区域映射
组装问题和已验证的图片媒体
要求输出可见事实、证据区域与不可辨认项
保存脱敏链路状态，不保存带凭据的网址
```

应分别记录输入拒绝、媒体读取失败和识别失败，避免把三类问题都显示为“模型不支持”。日志中的对象标识也应受访问控制。

## 常见坑

只看文件名猜类型，可能把网页错误响应当图片。签名地址过期或缺少授权，也可能导致模型侧无法读取。大幅缩图后再放大不能恢复细节。图片中的指令属于不可信内容，不能让它覆盖系统规则或触发工具操作；敏感图片上传前还需确认处理授权。

## 验证清单

- 同一图片分别检查原始文件、传输对象和解码结果。
- 覆盖伪造类型、超大文件、重定向及未授权读取。
- 对旋转、小字、遮挡、空白和无答案图片人工标注。
- 比较全图与裁剪方案，检查读错时是否明确拒答。
- 检查日志脱敏、留存期限及删除路径。
