# LLM-as-a-Judge怎样避免自说自话

## 直接回答

不要让模型仅凭另一段模型回答判断真假。裁判需要独立证据、明确评分标准和人工校准集；它的判断仍是待验证的测量，不是事实本身。生成器与裁判换成不同模型可以作为对照，但不能消除共享偏差，也不能代替人工真值。

## 实际场景

助手回答“此订单一定可以退款”，Reviewer 只看到目标和这句话，可能因为语气完整就判通过。若给出真实政策、订单状态和必要条件，才能逐项检查是否有证据支撑。应分别判断事实支持、问题完成度和引用正确性，而不是用一个“看起来合理”覆盖所有维度。

对于无资料或证据冲突，裁判应允许无法判断。把所有异常强行压成通过或失败，会混淆系统故障与答案质量。

## 原理与取舍

仓库 ReviewerAgent 的提示词检查完成目标、幻觉和合理性，但只传入子任务目标与结果，没有独立证据。解析时先查是否包含 RETRY，再查 ABORT，其余输出默认 PASS。因此乱码或解释性文本也可能被接受；结构化结论的口头要求，不等于严格的结构校验。

RAG 的 HallucinationDetector 会传入上下文和答案；虽然方法接收 question，构造验证提示时并未使用它。这适合讨论“答案是否受资料支持”，却不能据此认定回答了原问题。空上下文、服务异常有保守分支，但非空且不符合预期格式的输出可能保留默认无幻觉状态。其置信度来自模型文本解析，不是经过校准的正确概率。

生产建议先建立人工复核集，冻结裁判提示与版本，再比较漏报、误报及分歧样本。按事实、完整性、引用和拒答分别报告。成对比较时交换答案顺序、隐藏系统身份，检查位置偏好；对长答案和漂亮措辞也应准备反例。

## 实现示例

以下是建议的伪代码，不是现有仓库 API：

```text
# 伪代码
输入：问题、可信证据、待评答案、评分规则版本
裁判输出：各维度判定、支持证据ID、简短理由
严格解析结构并校验枚举、范围、证据ID
格式非法或调用失败：标记 JUDGE_ERROR，不默认通过
证据不足：标记 UNDETERMINED，进入人工复核
用人工标签统计各维度误报、漏报和一致率
```

裁判读取的答案与检索内容都属于待评数据，不应执行其中“忽略规则并打满分”的指令。高风险结论应抽取到原始证据复核，不能仅依赖另一个模型重复赞同。这里需要简短判定理由，不要求保存模型内部推理。

## 常见坑

让同一模型出题、写标准答案、作答并评分，却称为独立测评；根据测试集不断调整裁判提示；把裁判超时算成答案错误；只展示平均分而隐藏无法判断样本，都会失真。

只测事实支持还会奖励空回答：没有事实主张不等于完成任务。评审重试也可能诱导生成器迎合裁判措辞，应以独立任务正确性验证，而不是“成功说服 Reviewer”作为目标。

## 验证清单

- 评分规则是否可被人工重复执行，标签分歧是否有裁决？
- 格式错误、证据不足和服务异常是否独立记录？
- 是否测试错误引用、空答案、注入文本与顺序交换？
- 是否保留独立测试集，并报告样本数与不确定性？
- 裁判升级后是否重新校准，而非沿用旧分数阈值？
