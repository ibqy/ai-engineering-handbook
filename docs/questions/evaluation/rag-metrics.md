# RecallMRR与答案正确率有什么区别

## 直接回答

Recall@K 问“相关证据找回多少”，MRR@K 问“首条相关证据排得多靠前”，答案正确率问“生成的回答是否满足正确性标准”。三者测量对象不同，不能互相替代。证据齐全但模型读错，检索分数可以很高而答案错误；模型凭记忆答对，也不能反证本次检索有效。

## 实际场景

问题同时询问退款条件与例外，标注相关切片为 A、B。检索前两名是 X、A，只找回一半证据，但第一条相关结果仍在第二名。即使模型回答了退款条件，遗漏例外也可能使答案不完整。对于必须联合多个片段的问题，首条命中尤其不能代表证据充分。

标签对象还必须稳定：重新分块后沿用旧 chunk ID，会把标注失效误诊为算法退化。

## 原理与取舍

令相关 ID 集合去重后为 G，观察排名前 K 个位置。Recall 是不同相关命中数除以 G 的大小；单查询 RR 是首个命中名次的倒数，没有命中为零；MRR 是各查询 RR 的平均，不是平均名次的倒数。

仓库 EvalRunner 先截断再计算，各查询等权宏平均；Precision 分母固定为 K，即使返回不足 K 条也不变。空检索但有相关标签时计零；空数据集、缺相关标签和非法 K 被拒绝。标准答案字段不参与这些指标。

还要核对同名公式的细节。当前源码的 nDCG 理想命中数使用相关集合大小与实际返回列表长度的较小值，而评测文档公式写的是 K。返回不足 K 且相关标签更多时，两者可能不同；外部对比前应固定口径，不照抄名称便认定可比。

答案正确率则需要答案级标签或评分规则，明确完整性、事实错误及拒答如何判定。不能把“未检测到幻觉”直接当“答对”，因为空答、遗漏和答非所问也可能没有明显捏造。

## 实现示例

以下为伪代码和手算，不是测试运行输出：

```text
# 伪代码
G = {A, B}; 排名 = [X, A]; K = 2
Recall@2 = 1 / 2
Precision@2 = 1 / 2
RR@2 = 1 / 2
逐查询重复上述计算，平均RR得到MRR
答案另行核验退款条件与例外是否都正确
```

检索消融时固定语料、标签、候选与 K，仅改变待研究因素。答案消融则固定检索上下文，改变生成配置。若同时修改分块、模型和提示词，就难以把差异归因到某一层。

## 常见坑

RetrievalAblationTest 从冻结快照读取候选，以倒数名次构造合成分数，再比较融合结果；它没有执行真实向量或关键词索引查询。测试中的排名差异不是线上效果，也不能证明融合必然更好。

另一个坑是把未标注候选直接判为不相关。标签池可能不完整，新候选应补判；真正无答案的问题应进入拒答评测集，不能制造假相关 ID 来满足评估器输入要求。

## 验证清单

- 标签是否绑定文档、切片和语料版本，并经过人工复核？
- K、重复项、短列表及宏平均口径是否一致？
- 是否展示逐查询退化，而不只展示平均提升？
- 是否把合成排名、真实检索和答案评测分开报告？
- 是否冻结测试集，避免根据测试结果反复调参？
