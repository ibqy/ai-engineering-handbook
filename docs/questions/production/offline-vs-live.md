# 离线Demo测试通过为什么仍不能直接上线

## 直接回答

离线测试通过，只能说明受控输入、依赖和断言范围内的行为符合预期。它不能证明真实模型回答正确、供应商协议兼容、网络可靠、成本受控，更不能证明多租户授权和故障恢复已经具备。上线前要列清模拟点、内存状态和未覆盖链路，再用分层验证补足证据。

本文没有执行三个仓库的测试，不能报告它们本次全部通过。下面的上线步骤是生产设计建议，不是这些教学项目已经交付的生产保障。

## 实际场景

LangGraph4j 的 OfflineArithmeticChatModel 实现真实模型接口协议，但行为是按固定格式提取加法参数并生成工具请求。它适合验证模型与工具循环如何衔接，不代表远程模型的推理能力、格式稳定性或延迟。

ai-platform 的流式输出是本地字符串逐字符推送；TaskPublisher 使用进程内队列，TaskConsumer 用虚拟线程轮询并模拟处理。看到任务成功与重试状态，可以学习流程，但不能推断进程崩溃后任务不丢、跨实例只执行一次或吞吐满足业务需求。

## 原理与取舍

测试应拆成几个证据层。纯逻辑测试覆盖状态转换、参数验证和错误分类；组件测试覆盖真实序列化与存储边界；供应商契约测试检查认证、超时、工具格式、流式终止和用量字段；业务评测验证答案、引用和拒答；容量与故障测试再覆盖排队、取消、重启和恢复。

确定性离线测试便于快速定位回归，真实模型测试会受供应商变化与输出波动影响，两者都需要。对真实回答宜使用可检查的性质和业务标准，而不是盲目比较整段字符串。记录模型、提示词、数据集和知识库版本，才能解释结果变化。

教学安全边界必须单独处理：示例 token 前缀校验不是正式认证，正则注入检测不是完备防线，ConcurrentHashMap 缓存不提供跨实例一致性，本地线程与队列不提供持久任务保证。这些不能作为“先上线再完善”的默认基础。

## 实现示例

伪代码：生产验收的证据登记结构，不是测试平台 API。

```text
对每项能力登记：
  当前实现：真实依赖、离线模拟或进程内替代
  已验证范围：输入条件、断言与实际执行记录
  未覆盖范围：外部协议、权限、容量、恢复等
  上线证据：测试环境、版本、负责人、原始结果
  决策：通过、阻断或明确限制用途
仅在全部必要项有证据且无阻断项时允许进入灰度
```

例如“离线工具闭环正确”与“真实供应商工具调用兼容”应是不同记录。未执行测试就标记未验证，不能把源码中存在测试类、历史文档声称通过或本机编译成功当成本次验收结果。

## 常见坑

- 将模拟输出截图作为生产效果证明，隐去离线模式标识。
- 只验证 HTTP 成功，不验证工作流业务状态、引用和副作用。
- 把内存保存称为持久化，把任务编号称为幂等保障。
- 给教学服务配置真实密钥后直接开放公网，却未补身份与权限控制。
- 仅测试成功路径，不测试限流、部分输出、取消和恢复。

## 验证清单

- 枚举所有模拟实现与进程内存储，明确哪些只能用于本地学习。
- 使用受控账号和合成数据运行真实依赖契约验证，限制费用与外发范围。
- 对认证、跨租户访问、任务重启和副作用重放做独立验收。
- 建立质量、延迟、成本和失败率门槛，阈值由实际业务目标确定。
- 保存原始结果、环境和版本，失败项不得以演示成功替代。
