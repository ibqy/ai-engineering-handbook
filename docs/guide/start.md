# 如何使用这本手册

这不是另一套从头讲 API 的课程，也不是要求背诵的面试题库。它是已有 Java × AI 学习仓库的横向索引：**遇到问题，先得到一个判断，再找到可以验证的办法和对应的代码。**

## 三种阅读方式

- **问题驱动**：从[场景索引](../scenarios.md)找到症状，沿排查顺序阅读。
- **系统补齐**：从[问答目录](../index.md)按主题阅读，先基础，再高阶。
- **代码对照**：从[项目对照](../projects.md)进入已有课程，运行其中明确给出的测试或示例。

目录的输入框筛选标题、摘要、编号与标签；顶部的「全文搜索」检索完整正文。两者都在本地静态站点中完成，不调用大模型，也不需要 API Key。

## 一篇问答怎样读

| 部分 | 回答什么 |
| --- | --- |
| 直接回答 | 先用一两段给结论，不绕术语 |
| 实际场景 | 什么症状下应该看这道题 |
| 原理与取舍 | 为什么如此，什么时候不适用 |
| 实现示例 | 展示最小逻辑、数据流或算法，不假装是完整生产系统 |
| 常见坑 | 哪些看起来有效的做法会留下问题 |
| 验证清单 | 如何证明方案符合当前业务，而不是凭感觉 |
| 关联项目与参考 | 到哪里看真实代码，哪些部分只是教学简化 |

## 基础与高阶的区别

**基础**侧重概念边界与单条调用链：知道谁负责执行、哪个指标说明什么、哪里要设置约束。

**高阶**侧重多步骤、多租户、并发、恢复、成本和发布：不仅能跑，还要解释失败时会怎样、能不能重试、有没有权限。

高阶不等于使用更多框架。能够说明「这件事不需要 Agent」同样是工程能力。

## 示例与证据边界

- 文章中的伪代码用于说明设计，不保证可以复制到某个框架直接编译。
- 标为仓库摘录的代码以链接处实现和该仓库的依赖版本为准，不混用不同版本 API。
- 关联仓库是教学资产，不是生产认证；明确标出的未实现能力不能当作现成产品使用。
- 代码测试通过不等于真实模型、数据库或外部工具已经联调。真实集成必须单独验收。
- 搜索与引用不自动证明事实正确；需要检查来源是否真的支持回答。
- 内容复核日期表示文章检查时间，不表示每条外部链接或整个项目都在当天重新执行测试。

## 后续怎么补

新增问题保持稳定编号，一篇一文件。优先补充真实遇到的失败场景、可复现过程和取舍证据；不为凑数量重复解释概念。具体格式见[持续补充指南](./contributing.md)。
